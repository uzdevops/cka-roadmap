## Choosing a filesystem

| Filesystem | Notes |
|---|---|
| **ext4** | the safe default: mature, shrinkable, `resize2fs` grows online |
| **xfs** | RHEL's default: excellent with large files and parallel I/O; **grows only, never shrinks** |
| **btrfs** | snapshots, subvolumes, checksums, built-in RAID; more moving parts |
| **vfat/exfat** | removable media and EFI system partitions; no Unix permissions |
| **swap** | not a filesystem - `mkswap` (previous lesson) |

For the exam and most servers: ext4 unless told otherwise, xfs where RHEL
conventions apply.

## Making one

```bash
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.ext4 -L data /dev/sdb1              # with a LABEL
sudo mkfs.ext4 -m 1 -L data /dev/sdb1         # reserve 1% for root instead of the default 5%
sudo mkfs.xfs -L data /dev/sdb1
sudo mkfs.xfs -f /dev/sdb1                    # -f: overwrite an existing filesystem
sudo mkfs.vfat -F32 -n USB /dev/sdc1
sudo mkfs -t ext4 /dev/sdb1                   # the generic form
```

```bash
lsblk -f
# NAME FSTYPE LABEL UUID                                 MOUNTPOINTS
# sdb1 ext4   data  9f8e7d6c-5b4a-...
sudo blkid /dev/sdb1
```

`mkfs` **destroys** whatever was there. Check `lsblk`, `blkid` and
`mount` first; there is no undo.

## Labels and UUIDs

A **UUID** is generated by `mkfs` and is unique; a **label** is a name you
choose. Both are stable when device names change (`/dev/sdb` becoming
`/dev/sdc` after a reboot or a new disk) - which is why fstab should never
use `/dev/sdX`.

```bash
sudo blkid                                    # everything
sudo e2label /dev/sdb1 data                   # ext2/3/4: read or set the label
sudo tune2fs -L data /dev/sdb1                # the same
sudo xfs_admin -L data /dev/sdb1              # xfs (must be unmounted)
sudo xfs_admin -u /dev/sdb1                   # xfs: show the UUID
sudo tune2fs -U random /dev/sdb1              # ext4: new random UUID (after cloning a disk)
ls -l /dev/disk/by-uuid/ /dev/disk/by-label/
```

## Mounting it, once

```bash
sudo mkdir -p /mnt/data
sudo mount /dev/sdb1 /mnt/data
sudo mount -o noexec,nosuid /dev/sdb1 /mnt/data
sudo mount UUID=9f8e7d6c-... /mnt/data
sudo mount -t ext4 /dev/sdb1 /mnt/data
df -h /mnt/data; findmnt /mnt/data
sudo umount /mnt/data                          # or: umount /dev/sdb1
```

Persistent mounting is `/etc/fstab` - the next lesson.

## Tuning and inspecting ext4

```bash
sudo tune2fs -l /dev/sdb1 | head -30          # every parameter: block size, inode count, mount count, features
sudo tune2fs -m 1 /dev/sdb1                   # reserved blocks percentage
sudo tune2fs -c 30 -i 30d /dev/sdb1           # force a check every 30 mounts / 30 days
sudo tune2fs -O ^has_journal /dev/sdb1        # remove a feature (rarely wanted)
sudo dumpe2fs -h /dev/sdb1
sudo xfs_info /mnt/data                        # the xfs equivalent (on a MOUNTED filesystem)
```

The **inode count** is fixed at `mkfs` time: a filesystem full of tiny
files can exhaust inodes with space to spare (`df -i`). `mkfs.ext4 -i
8192` or `-N <count>` sets a denser ratio for such workloads - and it
cannot be changed later.

## Growing and shrinking

```bash
# ext4 - grow, online (mounted) or offline
sudo resize2fs /dev/vg0/data                   # to the size of the device
sudo resize2fs /dev/vg0/data 20G
# ext4 - SHRINK: must be UNMOUNTED and checked first
sudo umount /mnt/data
sudo e2fsck -f /dev/vg0/data
sudo resize2fs /dev/vg0/data 5G
# then shrink the LV/partition to match

# xfs - grow only, and only while MOUNTED
sudo xfs_growfs /mnt/data
sudo xfs_growfs -D 5242880 /mnt/data
```

The order is opposite for growing and shrinking: **grow** the device then
the filesystem; **shrink** the filesystem then the device. Doing it the
other way round loses data. (`lvextend -r` / `lvreduce -r` handle both
steps for you - the LVM lesson.)

## Checking and repairing

```bash
sudo umount /dev/sdb1                # NEVER check a mounted filesystem
sudo fsck /dev/sdb1
sudo fsck -n /dev/sdb1               # report only
sudo fsck -y /dev/sdb1               # answer yes to everything
sudo e2fsck -f -y /dev/sdb1          # force even if it looks clean
sudo xfs_repair /dev/sdb1            # xfs; -n for dry run
sudo xfs_repair -L /dev/sdb1         # zero a damaged log - LAST RESORT, loses recent writes
```

For the root filesystem: `sudo touch /forcefsck && sudo reboot`, or boot
into rescue mode.

## Copying and cloning

```bash
sudo dd if=/dev/sdb1 of=/dev/sdc1 bs=4M status=progress    # block copy - same size or larger target
sudo e2image -ra -p /dev/sdb1 /dev/sdc1                     # ext-aware clone, copies only used blocks
sudo tune2fs -U random /dev/sdc1                            # give the clone a NEW uuid, or fstab gets confused
sudo rsync -aHAX /mnt/src/ /mnt/dst/                        # file-level, filesystem-agnostic, preserves ACLs and xattrs
```

:::warning
Two duplicate UUIDs on one system make mounts non-deterministic: `mount
UUID=...` may pick either device. After any `dd` clone, change the copy's
UUID before both are visible to the same kernel.
:::

:::exam-tip
"Format /dev/sdb1 as ext4 with label X and mount it at /mnt/Y" →
`mkfs.ext4 -L X /dev/sdb1`, `mkdir -p /mnt/Y`, `mount`, then the fstab
line for persistence (next lesson), verified with `lsblk -f` and `df -h`.
If the task says xfs, remember it cannot be shrunk and is grown with
`xfs_growfs` while mounted.
:::
